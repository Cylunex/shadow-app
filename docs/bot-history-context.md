# Bot 历史定位与前后文

2026-11-06，源码 0.10.0（20）。补齐“搜索到旧消息后继续阅读”的流程；本批仅完成代码与合成验证，未部署、构建 APK 或安装。

## 参考与取舍

- [Telegram 搜索过滤](https://telegram.org/blog/filters-anonymous-admins-comments)：保留当前聊天范围与完整结果，先不增加全局搜索和复杂过滤器。
- [Mattermost 搜索](https://docs.mattermost.com/help/getting-started/searching)：参考从命中结果查看消息上下文的交互。手机使用独立的只读前后文页，返回时保留原搜索列表位置。
- [Compose 列表稳定键](https://developer.android.com/develop/ui/compose/lists#item-keys)：使用消息角色与 ID 作为键；向前追加分页后保留当前阅读位置。初次定位按锚点身份触发，普通翻页不会重复跳回。

## 交互

搜索结果支持字面关键词高亮、键盘搜索、已加载数量与“查看前后文”。高亮忽略大小写，不执行正则表达式，每条最多标记 500 处；服务端检索仍沿用 SQLite 的既有匹配规则。

打开后突出原消息，从该消息开始阅读，可向前／向后加载、回到定位消息、重新读取；非命中的相邻消息也会展示。历史页展示原说话者、日期与附件名称，可选择文字。该页不发送新消息、不下载附件，也不会把历史锚点当作聊天的最新位置。

首次最多展示前后各 30 条及原消息，共 61 条；继续每页最多 30 条，单次窗口最多 600 条。到达上限时可重新定位或返回搜索其他内容。前后文不进入离线缓存或系统保存状态；重建页面后需重新定位。断网时保留当前已读内容并提示，暂停翻页；恢复后按现有同步机制核对。

## 协议与失效

新增 handshake 能力 `messageContext` 和 `GET message-context?entryId=…&id=…&role=…&epoch=…`。响应包含 `generation / entryId / epoch / anchor / items / before / after`；`before` 与 `after` 分别继续向前／向后读取，不能同时传入。`limit` 默认 30、范围 1–100；初次最多 `2 * limit + 1` 条，分页最多 `limit` 条。

定位复用 history 对 sources／outbox 的同一可见性查询，没有独立消息副本。所有者、入口、遗忘、来源替代、投递状态与 epoch 过滤保持一致。顺序固定为时间升序、角色降序、ID 升序；相同时间甚至相同 ID 的输入和回复仍可区分。游标绑定入口、锚点 ID／角色、方向和 memory epoch，每次翻页重新验证原消息仍可见。

原消息不可见返回 404，历史版本失效返回 409。客户端清空上下文和旧搜索结果，提示重新搜索；历史搜索翻页收到 409 也清空旧结果。服务重启、联系人切换、能力撤回、401／403 均清理上下文；退出页面后的迟到响应不能重新发布内容。遗忘与更正通过现有 epoch／事件同步生效，不宣称断网期间可获知服务端撤回。
