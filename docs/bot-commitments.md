# 手机持续事项


后续 0.16.0 已增加完整集合搜索与分页，见[接手与检索增量](bot-browser-handoff.md)。以下最近 100 项说明仍适用于旧 `GET commitments` 和旧服务兼容路径。
2026-11-06；起点 App `f0c2e19`、Losna `ca2b8bf`，源码 0.15.0（25）。本轮只开发、合成验证、提交和推送，未部署、构建 APK 或安装；手机仍是 0.12.0（22）。

## 缺口与取舍

持续委托 commitment 及其原 work、等待条件和操作已由 Losna Continuity 提供。手机此前只有一次工作执行的入口，本轮增加当前伙伴的“持续事项”，不复制调度器、学习规则或事项存储。

本轮联网核对两项一手资料：

| 来源 | 采用 | 不采用 |
| --- | --- | --- |
| [Linear：父事项与子事项](https://linear.app/docs/parent-and-sub-issues) | 分开呈现持续目标和具体工作，并提供关联入口 | 不引入项目层级或默认联动完成；沿用现有 commitment／work 关系 |
| [Todoist：循环任务的完成](https://www.todoist.com/help/todoist/features/complete-a-task-with-a-recurring-date-dmI6SVqdP) | 区分一次执行结束与整个持续目标结束 | 不将持续委托变成日历循环任务，不新增手机定时执行 |

## 界面与操作

- 聊天菜单进入“持续事项”，按当前伙伴展示目标、真实状态、等待原因、下次检查时间和最近结果。筛选为跟进中／已结束／全部；“跟进中”包括暂停和等待。
- 展开后按服务端允许的动作显示暂停、继续、更新目标并继续、停止；只有 `user_judgment` 类型显示“确认目标已完成”。交付类型依实际工作结果结束；ongoing 不因一次工作完成而自动结束。
- 继续和更新沿用已有服务端语义：提交的正文替换完整目标，并作为本次执行要求。输入默认预填原目标，界面明确提示；不将一句补充悄悄覆盖原目标。页面跟踪类只开放可用的暂停、恢复和停止；到期不允许恢复，不提供修改目标或人工完成。
- 打开关联工作后沿用原详情、计划、执行记录和成果，返回时回到持续事项。无有效关联工作时不显示入口。新委托和更复杂的等待条件仍在聊天中说明，不新增创建表单或审批中心。
- 当前每次展示最近 100 项有效记录，按原创建位置倒序；筛选仅作用于这批记录，存在更多时明确提示。结果和等待原因分别最多 1000 字，结果截短会说明；没有声称全量检索或无限历史。

## 协议与恢复

- `commitmentDetails` 能力开放 `GET commitments?entryId=…&ifRevision=…`。响应包含 `generation / epoch / revision / items / hasMore / unchanged`，每项包含归属、版本、完成方式、等待信息、有效关联工作及 `allowedActions`。
- 修订哈希覆盖当前有效投影、入口、服务代次和记忆 epoch。条件相同返回空 items 与 `unchanged:true`，手机保留已有列表和展开状态；页面跟踪到期即使没有 Product 事件也会撤回恢复动作。旧服务只有 `commitments` 时显示兼容说明，可继续通过聊天处理。
- 服务端读取和命令都核对本人、事项入口、来源有效性、当前动作及目标版本。入口核对用于避免把委托投给错误伙伴，不把角色当作新的权限沙箱。已结束事项不再接受更新复活；来源失效须通过当前材料重新委托。旧快照字段保留并增补归属与动作，网页按当前入口筛选并不再提供无效的接续按钮。
- 手机前台页面约每四秒重新核对。网络或授权失败撤下旧内容和控件，切换伙伴／连接、进入后台或离开页面使在途读取失效；重启、epoch 和能力变化清理旧投影。不缓存持续事项正文到离线聊天副本。
- 动作沿用原 `POST commands`，传 `commitmentId / expectedVersion`。先加密持久化原命令 ID、动作、目标、正文和版本，再发送；回执丢失可按原编号重试，版本冲突保留原记录，不自动采用新版本重放。一项委托存在待确认操作时不再排入第二个动作。
- 本地状态升至版本 6，兼容读取 1–5；持续事项编辑草稿独立加密保存，不覆盖聊天草稿。发送时在同一次原子写入中消费匹配草稿并加入队列。磁盘失败不发请求；移除待发记录不代表撤回已执行的操作。旧版 App 无法读取版本 6，回退客户端前需另行规划资料兼容。

## 验证与剩余项

- 74 项 Kotlin 核心／真实 HTTP 合成集成、33 项 Android 单元／布局测试、编译及 Debug Lint 通过，无测试跳过。验证持久重试、磁盘失败、版本冲突、跨入口和连接失效、草稿迁移、条件读取、原工作接续、用户完成与遗忘撤回。
- Losna 语法检查及 715 项 Node 测试通过，无跳过。专项覆盖跨伙伴／本人隔离、100 项窗口、来源失效、结束状态、页面跟踪到期、重复回执和重启。
- 已检查 320dp、双倍字体及展开操作截图；实际临时 Runtime、Product 和 SQLite 的集成内容均为合成数据，没有真实模型／业务调用。真机交互和自然长期跟进仍待发布后的独立验收。
- 手机浏览器接手仍未接入；实时推送、设备会话撤销、伙伴服务端音色与跨端播放仍是独立后续能力。本轮不更改生产配置或外部业务权限。
