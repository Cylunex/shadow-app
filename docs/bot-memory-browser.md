# 共享记忆检索与分页

2026-11-06，源码 0.12.0（22）。补齐只能查看最近 100 条记忆的缺口；代码与合成验证完成，服务端已部署，原签名 APK 已覆盖安装，原登录与数据保留。

## 一手参考与取舍

- [Letta 官方 SDK 的 archival-memory 列表实现](https://github.com/letta-ai/letta-node/blob/main/src/resources/agents/passages.ts)：核对 `list` 的 before／after、limit、search 和排序参数，采用有界游标分页和文字搜索入口。Shadow 的游标额外绑定查询、类型和有效内容版本，不把偏移页码作为稳定位置。
- [Mem0 官方 Memory 实现](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py)：核对 `get_all`／`search` 的身份筛选、过期过滤与查询约束。采用先限定本人有效记忆、再查询与分类的顺序；本轮是字面关键词搜索，不引入语义检索、外部托管或另一份记忆库。
- 复用 Losna `Memory.active('owner', { explicit: true })`、来源版本与原 Product 命令。少提的内容仍可明确回查，已遗忘、被替代、过期、来源不再有效的内容不可返回；虚构情境保留独立类型。

上述源码于本轮只读核对，未安装新的第三方依赖，也未向外部服务提交用户记忆。

## 手机体验

共享记忆页支持搜索全部有效记忆，按共同经历、偏好、个人资料、持续话题、相处关系、虚构情境筛选；空搜索显示全部类型范围内的有效记忆。关键词最多 200 个 UTF-16 单元，按字面子串忽略大小写匹配，不解释正则或通配符。命中沿用聊天搜索的高亮显示。

新服务每页读取 50 条，按创建时间降序、同时间按 ID 降序；可继续加载，每次浏览最多保留 600 条，达到上限后提示缩小搜索范围。列表显示已加载数量，不假装是全库总量。来源与更正／少提／遗忘仍在当前页内完成；收起详情或按返回键回到原列表位置。

普通前台轮询使用条件读取：有效内容没有变化时保留全部已加载页面、阅读位置和展开的来源。内容变化后替换为当前首屏、收起旧详情；更正和遗忘仍使用原 command ID 与 expectedVersion，不自动更新版本重放。断网保留当前已读内容并提示重试，无法得知离线期间的远端撤回。

离开记忆页、退到后台、换连接或失去授权时清理正文与来源；回到前台重新读取。浏览状态和来源不进入磁盘缓存或系统保存状态。退出页面、收起详情、改搜索词后返回的旧请求不能重新发布旧内容。旧服务没有 `memoryBrowse` 时仍显示原最近 100 条，不显示不可用搜索控件。

## Product 协议

新增握手能力 `memoryBrowse`。扩展现有 `GET memories`，保留 `items` 字段供旧客户端使用；未带分页参数默认最多 100 条。

| 参数 | 含义 |
| --- | --- |
| query | 字面关键词，默认空，最长 200 |
| kind | 空或 episode／preference／profile／thread／relationship／play |
| limit | 1–100，默认 100，手机使用 50 |
| before | 上页返回的 next，不与 ifRevision 同用 |
| ifRevision | 前台检查已读取内容是否仍有效，与原查询／类型一起传入 |

响应包含 `generation / epoch / query / kind / revision / unchanged / items / next`。`revision` 是当前筛选下的有效集合摘要，含服务代次、memory epoch、稳定顺序、记忆版本及来源版本；每次通过原权威重算可见性，自然到期即使没有写入或事件也能改变摘要。相同摘要返回 `unchanged: true`，客户端保留原列表和游标。

游标包含查询、类型、摘要和最后一项稳定位置，最长 2000 字符；范围错误或非法参数返回 400，有效内容／服务代次变化返回 409。分页前重做可见性核验，不保留历史内容快照。手机在 409 时清空旧列表／详情、核对握手并重新读取；401／403 也清理内容。条件摘要只用于数据新鲜度，不能替代已有认证。

## 验证与限制

- 正式 Release 构建和 Lint 通过；真机已验证搜索控件、类型筛选及清除，进程重启后恢复原登录。公网验证记忆条件读取及双入口历史／前后文。未发送真实模型消息或执行生产记忆修改；大规模分页与修改撤回仍以合成用例为依据。

- App 50 项核心／真实 HTTP 合成集成、24 项 Android 单元／布局测试通过，Kotlin 编译和 Debug Lint 通过；320dp 搜索筛选截图已检查。
- 核心用例覆盖多页保持、条件刷新、版本冲突、服务重启、memory epoch、换搜索／退出／收起详情的迟到响应、登录实例变更、网络错误、404／403 和旧服务回退。
- 跨仓库 HTTP 使用真实 Losna Runtime／SQLite／Memory，构造 123 条合成记忆，完整翻页并执行更正、遗忘和旧游标拒绝；不加载生产配置、不调用真实模型。
- Losna 针对 127 条同时间记录验证无重漏、字面特殊字符、本人范围、参数与游标隔离、来源变更、自然过期、少提、遗忘和更正；全量检查结果见[服务端记录](https://github.com/Cylunex/shadow-losna/blob/main/docs/execution/bot-memory-browser-20261106.md)。
- 服务端仍通过现有 `active` 权威枚举有效记忆后筛选与排序，没有新索引或数据库迁移；大规模私有库的延迟未实测。本轮不宣称语义搜索、云端草稿或离线记忆库。
- App／Life／Media 继续共用现有 Authelia 的同一个用户账号，独立 client_id／API audience 只是协议登记与访问范围。本轮不修改身份中心、生产 OIDC 配置、账号或推送渠道。
