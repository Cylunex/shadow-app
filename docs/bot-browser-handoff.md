# 手机浏览器接手与持续事项检索

2026-11-06；源码 0.16.0（26）。本批仅开发、验证、提交和推送；未部署、构建 APK 或安装。手机仍为 0.12.0（22）。

## 一手参考与取舍

本轮重新访问官方文档，并核对 Losna 的 Browser / Product / Web、锁定 Playwright 1.64.1 的 `coreBundle.js` 中 Locator.nth、elementHandle 与 ElementHandle.click，以及原生 Repository、持久状态和生命周期实现。

| 来源 | 采用 | 不采用及原因 |
| --- | --- | --- |
| [Playwright Locators](https://playwright.dev/docs/locators) | 理解 Locator 会在动作时重新定位；普通自动化仍使用它 | 人工看到的 `eN` 不能长期绑定 `nth(N)`，网页插入控件后可能点到另一项 |
| [ElementHandle](https://playwright.dev/docs/api/class-elementhandle) | 本批人工快照引用绑定实际元素，并用 DOM 变动观察器撤销旧引用；及时释放句柄 | 官方一般推荐 Locator；这里只为短期“用户刚才看到的元素”采用句柄，不能把它当稳定的长期选择器 |
| [Compose 状态保存](https://developer.android.com/develop/ui/compose/state-saving) | 区分瞬时 UI 与持久恢复数据；网页输入只用 `remember` | 不把验证码／密码、页面截图和正文写入 saved state、聊天草稿、离线副本或待发队列 |
| [Linear Search](https://linear.app/docs/search)、[Pagination](https://linear.app/developers/pagination) | 全集合检索、显示命中片段、使用有界游标分页 | 不引入 GraphQL、项目管理或第二套目标库；继续原 Product / Continuity |

仅借鉴机制，没有复制上游代码、安装新插件、增加 MCP 或接入外部账号。

## 浏览器接手

- 聊天菜单的“浏览器接手”仅在 `browserHandoff` 能力可用时出现。列表限定当前伙伴和本人有效工作；可打开关联原事项。
- `GET browser-sessions?entryId=…` 返回 generation、epoch、当前 handoff 会话与版本。`POST browser/<id>` 携带 entryId、generation、expectedVersion；写操作另带 commandId，填写／点击使用刚读取的 ref。
- 手机显示读取时的截图、可展开文字、控件选择、一次性填写、点击、重新查看和交回入口。所有填写均掩码，不自动填密码、不向手机浏览器传递服务端 Cookie。
- “交回伙伴”只将浏览器从 handoff 变为 active，不启动 work、不等同目标完成。结果页保留“打开原事项”，继续委托仍走原 `work.resume`。
- 来源遗忘／缺失、工作取消／排除、跨伙伴、错误 owner、Host 代次或页面版本冲突均拒绝操作。排队后重新核对入口，异步读取完成后再次核对来源；另一设备读取会提升版本并使旧控件失效。
- 引用绑定当前实际 DOM 元素，观察主文档节点、属性和文字变化。变化后旧引用不再点击；重连只恢复地址，不重放点击。页面依然可能在实际交互期间变化，这不是第三方网站事务保证，业务结果仍要重新观察。
- 点击、填写前移除手机操作控件；只发一次请求。未知回执、网络失败或取消不生成重试按钮，不进入普通消息待发队列。重新读取页面后由用户核对真实结果，再决定下一步。
- 服务器保留原命令回执、无填写正文的参数摘要；新回执也不持久化可用于离线猜测输入的全文摘要。最近 512 次命令在同一进程可核对完整意图；重启后相同编号只返回原回执，绝不应用新填写值。历史旧格式回执仍可识别。
- 页面正文、截图和填写内容仅为瞬时展示；离开、切后台、身份／能力／来源变化或列表读取失败清除。HTTP JSON 响应 `no-store`；Android 沿用既有 FLAG_SECURE。专用服务端浏览器 Profile 与网站本身的存储仍按原浏览器语义保留，不能把“不写手机草稿”说成网站不会保存输入。
- Web 接手同步修正：当前伙伴过滤、版本／代次、迟到返回、来源撤回、掩码填写和未知结果不重放；旧打开的 Web 页面需要刷新以加载新协议。

限制：沿用主文档前 100 个候选控件、12000 字正文和当前视口截图；不含 iframe 内控件、滚动遥控、文件上传、select 选项编辑、第三方弹窗和任意网站接管。动态频繁变更页面可能要求重新读取。具体业务网站完整操作仍待实际运行验证。

## 持续事项完整检索

- 新 `commitmentBrowse` 能力和 `GET commitment-page` 支持 query、status、before、ifRevision、limit。旧 `GET commitments` 的最近 100 项响应保持兼容；旧服务不显示全量搜索入口。
- 搜索当前伙伴全部有效 commitment 的完整目标、完整结果和等待原因；字面匹配，不解释正则或通配符。搜索词最多 200 UTF-16 字符，片段最多 282 字符；状态为全部／跟进中／已结束，完成和取消归已结束。
- 原创建位置倒序分页，客户端每页 50、服务端最多 100；单次手机窗口最多 600 项并提示收窄搜索。总数是完整匹配数，不能用加载数量替代。
- 游标绑定入口、查询、状态、Host、epoch、集合及有效投影。页面跟踪到期、来源撤回、关联工作失效也改变修订，即使 commitment 本身没有写入。409 不拼接新旧页；条件刷新保留全部已加载页。请求失败清除管理控件，换伙伴清除查询，离开后迟到响应无效。
- 操作仍使用原 commitmentId / version / command ID，关联 Work 保持独立。没有把单次执行完成算成长目标完成，也不恢复已终止事项。返回关联工作后保留查询，重新核对修订。
- 当前实现扫描该入口有效集合并计算投影修订；没有大规模私有库性能证据，不宣称无限规模。全文件正文检索、历史执行分页和跨伙伴检索仍不在此协议中。
