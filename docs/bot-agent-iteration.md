# Bot / Agent 第二轮：可继续的事项与可读成果

2026-11-06。继续限定 Bot，不新增业务模块、主脑、设备控制或发布流程。

## 参考与本轮取舍

- [Muse 产品设计](https://muse.ai/blog/how-we-designed-muse)：长期主聊天、并行后台事项、活动与成果透明。本轮将已有 work 的状态、计划和执行记录放进原生详情，不复制目标库。
- [Grok Bot 文件与成果](https://docs.x.ai/grok-bot/files-and-results)：成果可查看，手机分享先进入输入框。本轮接入现有成果快照的只读文本预览，以及 Android 文本分享草稿。
- [DSH Bot / Tobs 明确归属](https://github.com/BotHarness/DeepSeekBot/blob/4de27aa5fa8bc50a59107a08bf8dd956bc0fdaf1/docs/adr/0035-session-ownership-is-explicit.md)：任务使用持久归属，不由 UI 顺序猜测。本轮继续／取消携带原 workId、entryId、version 和幂等命令 ID。
- [Eta](https://github.com/Mangi-11/Eta)：原生手机入口和可见执行反馈值得借鉴。本轮只实现用户主动分享的文本，不引入其 Agent Loop、系统权限、Root、通知抓取或屏幕采集。

资料按本次访问核实，仅参考机制，没有复制这些项目的代码或素材。

## 实施范围

1. 会话列表增加最近消息、时间、在办事项数量和搜索；展示已确认事实，不编造“正在思考”或已读状态。
2. 事项详情显示目标、计划、最新结果、近期执行记录和成果；继续补充／取消复用现有服务端 work 控制。
3. 待发队列扩展为统一消息／工作命令，兼容第一版加密状态；回执未知重试原 ID 和原版本，409 不自动换版本重放。
4. 文本成果在原生界面只读展示，限制长度、沿用权限与遗忘检查。HTML 也仅显示文本，不执行脚本，不转发 Cookie 给外部链接。
5. Android 分享文本／选中文字 → 选择伙伴 → 输入框编辑 → 用户发送；不自动读取链接或发送共享正文，不覆盖已有草稿。

## 验收边界

沿用 JVM、真实 Losna Runtime 合成 HTTP 流程、服务端完整测试和 Android 编译／Lint。新增覆盖跨角色操作拒绝、版本冲突、丢回执后恢复、遗忘后详情与成果撤回、旧状态兼容、分享不自动发送。

开发阶段不部署、不构建 APK；后续按用户明确指令发布。历史分页、附件上传、语音、设备工具、独立职责权限、跨业务接入继续后置。
