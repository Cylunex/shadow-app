# Shadow Bot 初期设计与实施顺序

2026-11-06。后续用户已要求继续补齐 Bot 日常体验，新增范围与完成边界见[日常体验设计](bot-everyday-experience.md)。本页保留初期范围；Losna 仓库较早的超级 App 方案仅作远期参考。

## 产品与边界

Shadow 是连接已有 Losna / DSH 的个人 Bot。打开后是角色／会话列表，点联系人进入持续聊天。角色可自定义，不预置生活、开发、理财、秘书职业；已有 Losna、doll 身份与历史保留。轻量 RP 由人格资料表达，不做 Tavern。

本期只交付 Bot：文字聊天、恢复、角色与人格资料、事项进度、共享记忆和连接设置。不做“今日”、业务空间、仪表盘、Life / Media / Foliant 接入。服务端现有领域能力保持原授权；客户端不承接第二套主脑、Agent 循环或记忆库。

## 最小结构

- `app`：Kotlin / Compose 界面、ViewModel、生命周期、Android Keystore 加密持久化。
- `bot-core`：纯 Kotlin 的模型、Product API、同步与待发送队列，可独立 JVM 验证。
- UI → ViewModel → BotRepository → ProductApi；UI 不拼请求、不读取服务端存储。导航使用固定路由类型，未来按真实需求增加目的地，不预建注册平台。
- 角色是持久联系人和会话归属，`entryId` 对应现有服务端入口。人格是可切换的表达与身份资料，`personaId` 不作为会话键、权限或业务模块。
- 复用 `main:owner:<entryId>`；消息使用服务端 source/outbox ID，待发命令在发送前生成 UUID 并持久化。名字、人设变更不新建会话。

## 协议与恢复

连接现有 `/losna/agent/api/`：handshake → snapshot → events → 状态变化后回读 snapshot。事件是失效通知，不是增量消息正文。服务重启代次变化、游标失效、回前台都重新握手并读取快照。

仅前台轮询；不让手机维持 Agent 执行。快照替换当前视图，不追加旧缓存，避免遗忘后旧内容重新出现。当前协议最多返回最近 200 条消息；历史分页不伪装已实现。

消息发送前将正文、entryId、command ID 保存到加密待发队列。请求失败或回执丢失保留原 ID；重试可更新 generation，但不得改正文或角色。服务端已接受不代表已回复或事项完成。恢复先读取快照，未确认消息由用户点击重试，避免离线数日后自动发送旧意图。401 停止同步并提示重新连接；不清除待核对命令。切换服务地址前必须先处理原连接待发消息。

## 登录与本地资料

先复用 DSH 根页面 launch-token → 签名 Cookie 的现有登录路径，不使用 `/connect` 创建另一种 operator。地址为 DSH 根地址（含反向代理前缀），例如 `https://example.com/dsh/`；产品接口位于该地址下 `losna/agent/api/`。

只接受 HTTPS、正常系统证书校验，不跟随跨站重定向。启动口令仅用于登录请求，不落盘、不记录日志。Cookie 与待发正文通过 Android Keystore / AES-GCM 加密并原子保存，禁用系统备份。已有 Cookie 到期后重新登录；设备管理、撤销和 refresh token 不属于已实现能力。代理路径兼容由实际部署验收确认，不凭离线测试宣称手机实网可用。

## 初期实施顺序

1. 替换旧多项目 WebView、蓝牙秤、Nexus 入口与相关构建配置；保留 Git 历史、忽略的本地配置、私有 SDK 和签名资料。
2. 原生角色列表、聊天、连接设置；实现文本发送、回执、断线重试、重启恢复，完成 JVM 协议测试和 Android 编译／静态检查，不构建 APK。
3. 在 Product API 内最小扩展角色／人格与共享记忆读取；复用 Personas 和 Memory 权威。事项只展示服务端真实状态，继续通过聊天补充或取消，不复制控制面。
4. 记录验证范围与未完成项，分别提交并推送 App 和 Losna；生产部署、APK、真机实网验收另行执行。

附件、语音、历史翻页、推送通知、长期设备授权、角色权限隔离和业务模块合并后置。职责说明是协作偏好，不构成权限隔离。以后需要独立职责时在已有服务端入口和人格边界增量实现，不用客户端本地角色冒充隔离 Agent。

## 本轮实现落点

上述 1–4 的代码与合成验证已完成，详见[实现记录](implementation-status.md)。联系人可以在 App 新建，id / 名字保存在原 Losna 状态库，使用既有主模型、禁用 QQ；人格卡仍由独立 Personas 权威保存。角色在初期表示联系人及持续会话归属，不承担职责权限隔离。未实现能力与生产验收另列，不计入已完成。
